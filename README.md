# 光伏固定支架 3D 设计

根据固定倾角地面光伏支架图纸构建的交互式 three.js 模型。支持调整组件、榀距、坡度和固定方式，查看构件尺寸、檩条分段及连接节点。

- 仓库：[Alan-T/pv-3d-demo](https://github.com/Alan-T/pv-3d-demo)
- 在线演示：[光伏固定支架 3D 设计](http://47.116.75.159:257/)
- 技术：Vue 3 单文件组件、JavaScript ES Modules、three.js r128、OrbitControls，使用 Vite 开发和构建。
- 使用 Yarn 管理依赖，three.js 固定为 `0.128.0`，OrbitControls 从同一个 `three` 包导入。

## 本地启动

需要使用支持 WebGL 和 ES Modules 的现代浏览器。

### Vite 开发与构建

使用 Node.js `20.19+` 或 `22.12+` 和 Yarn `1.22.22`。项目通过 `packageManager` 声明 Yarn 版本，已安装 Corepack 的环境可运行 `corepack enable` 启用 Yarn。在项目根目录运行：

```powershell
yarn install --frozen-lockfile
yarn dev
```

打开终端显示的地址（默认 `http://localhost:5173/`）。修改前端文件时，Vite 会更新或刷新页面。

```powershell
yarn test
yarn build
yarn preview
```

`yarn test` 运行现有 Node.js 测试，`yarn build` 生成 `dist/`，`yarn preview` 在本机预览构建产物（默认 `http://localhost:4173/`）。提交 `yarn.lock` 以固定依赖版本。

`vite.config.js` 集中配置开发端口 `5173`、预览端口 `4173` 和构建目录 `dist/`。Vite 启动及构建时会自动加载该文件。

### Windows 一键预览

双击根目录的 `启动预览.bat`，脚本会检查 Node.js 和 Yarn，按锁文件安装依赖，在 `127.0.0.1:8765` 启动 Vite 后台服务，等待就绪后自动打开浏览器。

已有项目服务时直接打开页面；端口被其他服务占用时会提示。关闭浏览器不会停止后台服务，需要停止时可在任务管理器中确认对应的 Node.js 进程后结束。

### 部署服务本地验证

安装依赖后，在项目根目录构建并启动静态服务：

```powershell
yarn build
node deploy/serve.js
```

打开 [本地预览](http://localhost:8765/)，按 `Ctrl+C` 停止服务。服务默认监听 `0.0.0.0:8765`；只允许本机访问或更换端口时，可在 PowerShell 设置：

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '8766'
node deploy/serve.js
```

此时访问 `http://localhost:8766/`。静态服务读取 `dist/`，修改源码后需要重新执行 `yarn build`。一键脚本使用 Vite 开发服务，固定使用 8765 端口。

ES Modules 需要通过 HTTP 加载，直接双击 `index.html` 使用 `file://` 会受到浏览器模块加载限制。

## 参数与计算规则

尺寸以毫米为单位，渲染时换算为米。坐标约定：X 向北、Y 向上、Z 向东。

### 图纸方案

| 默认参数 | 图纸一 | 图纸二 |
| --- | --- | --- |
| 组件倾角 | 25° | 15° |
| 沿坡排数 × 东西列数 | 2 × 28 | 3 × 27 |
| 前后立柱间距 | 2900 | 3700 |
| 首末跨 / 中间跨榀距 | 2800 / 2800 | 3250 / 3250 |
| 南北坡度 | −5% | −2% |
| 东西坡度 | 0% | 0% |
| 外斜撑 | 无 | 有 |

两套方案默认组件尺寸均为 `2382×1134×35`，固定方式为螺栓，檩条最大长度为 9000。组件长、宽、厚可修改；沿坡和东西向组件间隙固定为 20。图纸尺寸、推算值和假设可结合页面的核对表与说明查看。

### 阵列、榀距与坡度

- 阵列宽 = 列数 × 组件宽 +（列数 − 1）× 20。
- 檩条总长 = 阵列宽 + 两端伸出量：螺栓固定每端 50，压块固定每端 100。
- 榀数取两端悬挑不超过首末跨榀距 0.4 倍的最少榀数；组件列数过少、无法放下相应榀数时会提示。
- 南北坡度正值表示北高南低，负值表示北低南高。前柱处地面作为 ±0，后柱按实际坡面保持埋深。侧视中水平基线不动，非零坡度时显示坡度线及后柱处高差。
- 东西坡度正值表示东高西低，负值表示东低西高。榀距、阵列宽和檩条长度按沿坡长度计，各榀立柱保持竖直。

若东西坡度百分数为 `s`，令 `i = s / 100`：

```text
水平距离 = 沿坡长度 / √(1 + i²)
高差     = 水平距离 × i
```

### 檩条切割与连接件

最大长度可选 `5700 / 7200 / 9000`，与表面处理无关联。算法位于 `src/purlin-cut.js` 的 `cutPurlin()`：

1. 总长不超过上限时保留一段。
2. 与二维自动切割一致，从理论最少段数开始，把平均段长四舍五入到 100，再补偿接缝来初始化接头位置。
3. 两种固定方式均使用二维的组件缝位置避让（含首块前方虚拟缝），距离至少 300；接头须距至少一榀 300～1000。
4. 逐个接头按二维的累加规则以 50 为步长调整；每个接头最多调整 400 次。分段不合格则增加一段重算，最多尝试 5 组段数，不再以段长均匀为优化目标。
5. 接缝宽 4，实际段长扣除间隙；总长等于各段长度与全部接缝长度之和。

无可行解时给出提示，并暂以通长檩条显示。与二维的异常处理不同，三维不会采用调整超限后仍不满足避让的位置，也不接受零长度或负长度段。分段长度可在俯视 / 垂直组件视图及计算结果中查看。图纸一最大长度 9000 时，分段为 7000 / 6800 / 6900 / 8050 / 5712，四处接缝各 4，总长 34478。

默认檩条为 **C100*55*15*1.8**；连接件为无卷边 **U108*55*3.0，长 240**，每个接头使用 8 套 M12×35（上下翼板各 2 套、腹板 4 套）。连接件随“按图纸配色”切换颜色。“檩条-檩条”节点预览实际接头。

连接件纵向孔位目前为模型假设，具体值见 `src/parts/purlin.js` 中的 `splice`。

### 默认连接规格

| 位置 | 规格 / 规则 |
| --- | --- |
| 组件安装孔 | M8×22 外六角螺栓，螺栓头和螺母下各有平垫 |
| 中压块 / 边压块 | M8×35 内六角螺栓，压块长度默认 50、可调 |
| 斜撑、立柱、斜梁及檩托 | M12，螺母下一个平垫、一个弹垫 |
| 斜撑端孔 | 孔心距端头 35 |
| 立柱顶部安装孔 | 孔心距柱顶 50，竖向长圆孔在立柱上 |

## 代码结构

`src/main.js` 将 Vue 根组件 `App.vue` 挂载到 `index.html`。页面控件、结果表格和视图按钮使用 Vue 模板与事件绑定。`App.vue` 在挂载时创建 3D 场景，在卸载时释放动画循环、监听器、控制器和渲染资源。`designer.js` 接收页面操作并向 Vue 提供普通数据快照，Three.js 对象由场景模块管理。参数和求解逻辑仍通过 ES Modules 共享。`deploy/serve.js` 是独立的 Node.js CommonJS 脚本。

| --- | --- |
| `index.html` / `style.css` | Vue 挂载入口和全局样式 |

| `deploy/` | 静态服务及 systemd 配置 |

构件的 `build(c)` 接收参数 `P`、求解结果 `S`、布置 `layout`、方向向量、模型分组和螺栓收集器。新增构件时，在 `src/parts/` 实现并导出构建函数，在 `src/model.js` 中导入并调用。螺栓模块提供收集器，统一生成实例化网格。

构件现由 `createBracket(parameters, dependencies)` 统一创建，各文件导出 `PostPart`、`BeamPart` 等类，通过 `new` 创建实例。构造函数直接解构 options，显式接收截面与连接规格、材质、截面几何工具和资源跟踪器；构建函数接收本次支架的上下文。`parts` 不直接导入页面配置和材质模块，几何缓存属于当前构件实例。`model.js` 是页面默认配置的组装入口。

立柱、斜梁、斜撑和檩条通过注入的 `createSectionGeometry(section)` 创建杆件，檩条通过 `createSectionCapGeometry(section)` 创建剖切封口。两者共用 `createSectionShape(section)`，截面模块只依赖 three.js，不读取页面配置、材质或运行状态。返回的几何体由构件通过 `track` 管理释放。

截面尺寸以 mm 输入：`{ type: 'C', d: 100, f: 55, l: 15, t: 1.8 }` 表示 C 型钢，省略 `type` 时兼容现有 C 型钢参数；`{ type: 'roundTube', d: 100, t: 3 }` 表示圆管，`d` 为外径。局部 x 沿截面高度，y 沿截面宽度，z 为杆件轴向，几何体沿 z 拉伸 1 m，再由构件放置矩阵缩放到实际长度。C 型钢腹板外表面在 y=0；圆管外包络从 y=0 开始，中心为 `(0, d/2)`。

圆管目前仅支持截面几何生成，尚未加入页面选型。立柱换成圆管时，还需要适配放置基准、连接节点、尺寸标注与重量计算，不能只替换截面参数。后续增加截面类型，在截面模块中添加轮廓生成函数和类型分支即可，构件继续使用同一几何接口。

修改后刷新浏览器即可。建议核对两套方案、非零坡度、两种固定方式及受影响节点。

浏览器控制台保留 `window.pvDemo` 调试接口：

```js
pvDemo.P;                 // 当前参数
pvDemo.state;             // 求解结果、布置与视图信息
pvDemo.setView('top');    // 切换俯视图
pvDemo.P.maxPurlin = 7200;
pvDemo.rebuild();         // 修改参数后重建
```

## 部署与维护

执行 `yarn build` 后，将 `dist/` 内容发布到静态 HTTP 服务的站点根目录。`yarn preview` 用于本机预览。

项目提供的 systemd 服务使用 `deploy/serve.js` 托管 `dist/`，部署目录为 `/opt/pv-3d-demo`，服务名为 `pv-3d-demo`，监听 257 端口。

`deploy/serve.js` 仅依赖 Node.js 内置模块，支持 gzip、基于内容的 ETag 与缓存校验。启动前需要存在 `dist/index.html`，服务根目录为 `dist/`。

安装、构建并打包运行所需文件：

```powershell
yarn install --frozen-lockfile
yarn build
tar -czf pv-3d-demo.tar.gz dist deploy
```

服务器更新步骤：

1. 上传压缩包并核对校验值。
2. 备份当前 `/opt/pv-3d-demo`。
3. 将 `dist/` 和 `deploy/` 解压覆盖到该目录，保留现有服务配置。服务运行时只需要 Node.js。
4. 只更新前端资源无需重启；修改 `deploy/serve.js` 后重启服务。
5. 检查入口及模块资源、模型加载和浏览器控制台。

```sh
sudo systemctl restart pv-3d-demo
sudo systemctl status pv-3d-demo
sudo journalctl -u pv-3d-demo -n 50 --no-pager
```

首次安装参考 `deploy/pv-3d-demo.service`，确认实际 Node.js 路径、运行用户及目录权限。该文件为低端口 257 配置了 `CAP_NET_BIND_SERVICE`。

## 常见问题

- **双击 HTML 加载失败**：使用一键脚本或 HTTP 服务，不使用 `file://`。
- **找不到 Node.js**：安装后重新打开终端，通过 `node --version` 确认可用。
- **端口被占用**：关闭对应服务，或使用命令行指定其他端口。
- **一直加载或模型空白**：检查 WebGL、控制台报错，以及入口和模块资源是否返回 200 与 JavaScript MIME 类型。
- **更新后仍显示旧内容**：强制刷新，并确认服务器文件已更新。
- **檩条没有分段**：总长可能未超过上限；若提示切割无可行解，调整榀距或最大长度。

### 构件实例

立柱和斜撑按位置分别实例化：`frontPost`、`rearPost`、`frontBrace`、`rearBrace`，启用外斜撑后再创建 `frontOuterBrace`、`rearOuterBrace`。它们接收单独的 `section`、`material` 和位置 / 节点参数；连接板由组装层单独构建，避免内外斜撑重复生成连接板。实例可从 `createBracket()` 返回值的 `instances` 读取。

```js
const post = new PostPart({
  postFSection: frontSection,
  postRSection: rearSection,
  postMaterial, buriedMaterial, extrudeC, track,
});
post.build(context);
```

`bracket.js` 根据 `partOptions` 创建完整支架的构件实例；组装器显式调用 `parts.post.build(context)` 等方法，连接件在所属构件内单独实例化。

### 组件锯齿垫圈

组件采用螺栓固定时，可勾选“包含锯齿垫圈”（默认关闭），将组件上方螺栓头下的普通平垫替换为锯齿垫圈；下方大平垫及弹垫不变。切换压块固定后，该选项隐藏且不作用于压块。锯齿垫圈参考外齿扭转结构：平整内环、18 个窄切口外齿，齿尖上下翘起，H≈3S。图中未给具体数值，暂按外径 Ø16、内径 Ø8.8、板厚 S=0.6、总高 H=1.8 mm 示意；螺栓头随总高调整，公称杆长仍为22 mm。

### 立柱拉杆

- 前排、后排分别选择无、首末跨、全部跨或自定义；自定义可逐跨勾选。默认启用首末跨，未启用的跨不生成实体。可单独切换显示；截面下拉框提供 `L35*35*1.6`、`C59*39*8*1.6`、`C60*40*10*1.6`，默认 `C59*39*8*1.6`，暂不区分材质牌号。L 型角钢贴柱的一肢以螺栓轴线居中，截面选择同步影响模型和钢材估重。
- 孔位参考二维 `TopView.vue` 的 `calculateXY/getOptimalSolution`：扣除埋深、斜撑安装高度及 200 mm 后，孔高差按 100 mm 递增，柱顶余量在 150–300 mm 内优先接近 225 mm。高度不够形成 X 时使用一根水平杆；安装空间不足则提示并不生成。
- 直埋柱下料长度沿用二维：`Math.round(Math.hypot(水平跨距, 上下孔高差 ± 东西坡高) / 10) * 10 + 270`。前后排分别计算，按规格长度统计数量并计入钢材估重。
- 二维坡高使用 `跨距 × 坡度`，模型实际榀位使用 `跨距 × sin(atan(坡度))`；下料长度保留前者，实体孔位对准实际榀位，多出的端部余量平分，不改变既有支架坐标。
- 当前仅适配直埋 C 型立柱；X 形两根暂放在立柱两侧翼缘外侧以避免穿插，每根两端各一套 M12×35 外六角螺栓及螺母，两面平垫、螺母侧弹垫，随连接件开关显示并计入数量；尚未对型材做真实孔洞切削。圆管抱箍、螺旋桩的孔距及埋深修正规则未启用。
- 验证：`yarn node --test tests/post-tie-layout.test.mjs`。

### 檩条拉杆

- 双立柱体系按二维 `TopView.vue` 布置：每跨中点一套贯通拉杆；可选择无、全部跨、剔除首末跨、自定义（逐跨勾选）。与立柱拉杆一致，自定义逐跨开关使用数组（0 不安装、1 安装），默认空数组；每次切换到自定义时沿用当前布置，恢复图纸参数时重置。图纸一默认全部跨，图纸二保留原图不安装的配置。
- 长度 = 首末檩条间距 + 两端各 85 mm，四舍五入至毫米。图纸一为 3974 mm × 12 套，仅中间跨为 10 套。
- 截面与立柱拉杆共用 `L35*35*1.6`、`C59*39*8*1.6`、`C60*40*10*1.6` 三个选项，默认 `L35*35*1.6`，暂不区分材质牌号。L 型水平肢贴檩条下翼缘底面；C 型腹板贴底、槽口朝下，腹板宽度沿东西向、孔位位于腹板中线。每个檩条交点一套 M12×35 外六角螺栓及螺母（沿用既有连接规格），两面平垫、螺母侧弹垫；头在檩条槽内，螺母在拉杆安装面下面。拉杆安装面和檩条下翼缘使用真实 Ø14 通孔（孔径暂定）。图纸一共48套，随连接件开关显示。
- 随东西坡度布置，计入钢材估重；独立“檩条拉杆”显示开关，侧视和节点详图隐藏。
- `src/purlin-tie-layout.js` 负责布置与长度；`src/parts/purlin-tie.js` 负责实体；`section-geometry.js` 增加独立 L 型角钢轮廓。
- 验证：`yarn node --test tests/purlin-tie-layout.test.mjs`。

立柱拉杆东西坡度选长规则：前、后排及各跨分别计算平地长度与两根实际长度（均按原规则取整）。两根与平地长度的差值都在 ±100 mm 内（含边界），则两根均使用平地长度；任一根超出，两根均采用各自实际长度。模型长度、数量统计和估重使用选定长度，安装孔坐标保持实际坡度位置。

### 檩条连接件选择

页面“檩条连接件”下拉框提供清单去重后的14种规格（按高度、翼缘宽度、板厚、长度升序）（高度*翼缘宽*板厚*长度），由用户手动选择，不随檩条截面变化自动切换。图纸一默认 U108*55*3.0*240，图纸二默认 U98*55*3.0*220，恢复图纸参数时一并恢复。规格名称清单在 config.js 的 PURLIN_CONNECTOR_SPECS 中维护，src/purlin-connector-spec.js 负责名称解析与孔位；模型、螺栓、节点文字、剖切范围及数量统计使用所选规格。

220长：腹板孔距30/50/60/50/30，上下翼板孔距110；240长：腹板孔距35/50/70/50/35，上下翼板孔距120。连接件具有真实14×25长圆孔，每个接头8套M12×35，翼板螺栓夹紧距离包含装配间隙。55翼缘孔心距外背30，45翼缘为23；53翼缘孔位暂沿用宽翼30。节点文字、剖切范围、数量统计随所选规格更新。
